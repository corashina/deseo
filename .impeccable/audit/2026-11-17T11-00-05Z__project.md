## Implementation Integrity Verdict

**Pass.** The code expresses a coherent, product-specific system: "The Shared Notebook" with owner colors, a name beside each color, a chat-first Today, and a flat-card portal. It does not look interchangeable with an unrelated product.

Deterministic evidence:
- **Source detector** (`impeccable detect --json apps/web/src apps/site`): exit 0, **0 findings** after the project exceptions in `.impeccable/config.json`.
- **Rendered detector** (37 pages): 6 findings on 5 pages, 31 pages clean. All 6 are false positives:
  - `kicker-above-heading` ×4 (Today, Event detail, Idea detail, Memory detail, on `span.eyebrow`). DESIGN.md asks for an eyebrow (date or record type) above the title, and the config records this exception. The exception is scoped to `apps/web/src/**`, so it does not match the URL-based rendered results. **False positive (project exception).**
  - `nested-cards` ×2 (`.calendar-toolbar > .view-tabs` on Calendar, `.view-tabs` on Tasks). `.view-tabs` is the segmented control that DESIGN.md specifies ("View tabs and owner filters are segmented controls"). It is a 4px-padded track with a canvas fill, not a content card. **False positive.**

Visual judgment, kept separate: the verified drift is in component consistency (dialogs, the note-card spec) and in literal values. It is not in the visual system.

## Detailed Findings by Severity

### P2 Minor

**[P2] The Today conversation is squeezed on phones and tablets**
- **Location**: `apps/web/src/styles/messages.css` (`.message-composer`, `.message-composer textarea { min-height: 88px }`, `.conversation-page > .conversation { min-height: 160px }`) and `planning.css` / `shell.css` (Today fills `100dvh`)
- **Category**: Responsive
- **Evidence**: `today-390.png` and `today-390-dark.png`: in an 844px window, the composer card (label, 88px textarea, button, three links) is about 290px tall. The header, chip, and pinned note take about 330px. One message is visible. `today-768.png` shows about 1.5 messages.
- **Impact**: The main job of Today on a phone is reading and replying, and the reader must scroll a 170px strip to read the conversation.
- **Recommendation**: Below 768px, start the textarea at one or two rows and let it grow while the user types. Put Send on the same row. Move the three Add links into one row or a menu. Optionally, hide the page header eyebrow on phones.
- **Suggested command**: `/impeccable adapt`

**[P2] Dialog actions do not follow one pattern**
- **Location**: `features/calendar/pages/EventDetailPage.tsx:83`, `EventFormPage.tsx:150`, `features/tasks/pages/TaskDetailPage.tsx:90`, `features/tasks/pages/TasksPage.tsx:121`, `features/memories/pages/MemoryDetailPage.tsx:58`, `features/calendar/ideas/pages/IdeaDetailPage.tsx:55`, and `features/pair/pages/WaitingPage.tsx:49` have no Cancel. `features/messages/components/Conversation.tsx:138` puts Confirm deletion and Cancel side by side with no `.actions` wrapper, and `dialog` has no button spacing rule, so the buttons touch.
- **Category**: Implementation Integrity
- **Standard**: DESIGN.md › Dialogs: "A dialog with an action also has a Cancel button beside it." Settings is the one dialog that does it correctly.
- **Impact**: The same decision looks different on each screen. The only exit is the X icon. The two buttons in the Delete message dialog run together.
- **Recommendation**: Give `Dialog` an `actions` slot that renders a `.actions` row with the given action and a Cancel bound to `onClose`. Use it in all 9 action dialogs.
- **Suggested command**: `/impeccable harden`

**[P2] Message signals refetch more data than they change**
- **Location**: `apps/web/src/lib/realtime.ts:15` (`invalidate([feature, …], ['today', …])`), `features/messages/queries.ts` (an infinite query under the `messages` root), and `features/today/queries.ts` (the `notes` result, which is never read)
- **Category**: Performance
- **Impact**: Messages are the most frequent signal. Each incoming message refetches every loaded conversation page in sequence, the unread count, the pinned notes, and `get_today` with `latest_memory`. A long session with older pages loaded makes N+4 requests per message.
- **Recommendation**: Do not invalidate `today` on message signals. The portal reads notes from `listPinnedNotes`, and the `notes` array from `get_today` is unused, so remove it from the client path. For the conversation, fetch the newest page only (use `refetchPage`, or reset to the first page when the reader is at the latest message).
- **Suggested command**: `/impeccable optimize`

**[P2] The type scale has no tokens**
- **Location**: `font-size` literals (12, 14, 15, 16, 19, 30, 40, 48px) in `base.css`, `calendar.css`, `controls.css`, `memories.css`, `messages.css`, `planning.css`, `settings.css`, and `apps/site/src/site.css`. The site restates h2 and h3 in `.soon h2`. Settings restates the title style in `.paired-members h3`.
- **Category**: Theming
- **Impact**: The values match DESIGN.md today. But the override says type comes from `brand/tokens.json` and the frontmatter, and `tokens.json` has no type. A change to the scale must be made by hand in about 40 places, so the two apps can drift.
- **Recommendation**: Add the frontmatter typography roles to `tokens.json` (both files in one change, per the One Change Rule). Emit `--type-*` variables from `tokens-css.ts`. Replace the literals with those variables.
- **Suggested command**: `/impeccable typeset`

### P3 Polish

**[P3] Raw and off-scale values outside the token pipeline**
- **Location**: `apps/site/src/site.css` `.badge { padding: 2px 10px }` (10px is off-scale). `base.css` `.page-header { gap: 16px 24px; margin-bottom: 32px }`, `planning.css` `.section-heading` and `.idea-grid`, and `shell.css` `.mobile-account { padding: 7px }` use raw px for on-scale spacing. `apps/web/index.html` hard-codes `theme-color` `#FAF7F5` / `#14111B`, while the site generates the same values from tokens in `vite.config.js`. The portal injects token CSS at runtime from `main.tsx`; the site injects it at build time.
- **Category**: Theming
- **Recommendation**: Use `var(--space-*)` throughout. Move the portal's token `<style>` and `theme-color` metas into a Vite `transformIndexHtml` plugin, as the site does, so both apps share one path and the canvas color is set before any script runs.
- **Suggested command**: `/impeccable polish`

**[P3] Spec drift between DESIGN.md and the code**
- **Location**: The DESIGN.md frontmatter `note-card` sets `rounded: card` (20px) and padding 24px, but `.note-card` uses `--radius-control` (12px) and 12/16px padding (the prose asks for "compact rows"). The DESIGN.md "Do" list says to use `on-action` text and `action-border` on primary buttons, which contradicts the Buttons section (`primary` fill). `TasksPage.tsx:119` shows **Remove list** as a `danger` button on the page, but DESIGN says delete stays secondary on the page and the dialog holds the destructive button. Tokens `--shadow-popover`, `--shadow-selected`, `--duration-feedback`, and `--ease` live only in `styles/tokens.css`.
- **Category**: Implementation Integrity
- **Recommendation**: Update the note-card frontmatter to the compact values, fix the "Do" line, make Remove list secondary, and record the motion and shadow tokens in the frontmatter.
- **Suggested command**: `/impeccable document`

**[P3] The Calendar falls back to a hard-coded timezone**
- **Location**: `features/calendar/pages/CalendarPage.tsx:21`, `zone: … : 'Europe/Warsaw'`
- **Category**: Implementation Integrity
- **Impact**: It is unreachable on an active pair, but it is a product-specific literal in a timezone-sensitive path. Use the profile timezone, as the fallback on the next line does.
- **Suggested command**: `/impeccable harden`

**[P3] At 390px, owner filters wrap to three or four lines**
- **Location**: `calendar.css` `@media (max-width: 767px) .owner-filters` (a 2×2 grid)
- **Category**: Responsive
- **Evidence**: `calendar-390.png`: with long stress-test names, each owner segment is about 100px tall, and the pressed "Everyone" segment becomes a large raised block.
- **Recommendation**: Clamp owner labels to one line with an ellipsis (the `title` keeps the full name). Or show the owner dot with a short name and keep the full name in the agenda rows.
- **Suggested command**: `/impeccable adapt`

**[P3] Little headroom in the first-load budget, and the font is found late**
- **Location**: `apps/web/scripts/check-size.mjs` (budget 205 kB), `apps/web/dist/index.html` (on disk)
- **Category**: Performance
- **Evidence**: The on-disk build (possibly stale) loads about 199 kB gzip on first load. Of this, about 77 kB is the chunk that holds supabase-js and zod, and about 75 kB is the entry. That leaves about 6 kB of headroom. Manrope's latin woff2 has no preload, so the browser finds it only after the CSS loads.
- **Recommendation**: Keep supabase-js realtime and storage out of the entry path where possible. Add `<link rel="preload" as="font" type="font/woff2" crossorigin>` for the latin subset through the Vite plugin from the finding above.
- **Suggested command**: `/impeccable optimize`

## Patterns & Systemic Issues

- **Literal values beside a good token system.** Colors are fully tokenized (no hex in any component or stylesheet, except the deliberate JPEG flatten fill in `prepare.ts`). Type sizes and some spacing values are still repeated px literals in every stylesheet.
- **Shared components without shared slots.** `Dialog`, page headers, and action rows each repeat their layout at each call site, so details such as Cancel and the button gap drift from screen to screen.
- **Broad realtime invalidation.** Every signal invalidates its whole feature root and Today. This is correct, but it is broader than needed on the message path.

## Positive Findings

- **One token source for two apps.** `tokens.json` → `tokenCss` feeds the portal at runtime and the site at build time. Dark mode follows the device with no script, and each captured dark screen (Today, Calendar, Tasks, Welcome, Event detail, site home) keeps owner colors, contrast pairs, and the brand icon variant.
- **Route-level code splitting with early fetch.** Every page is `lazy`. The router starts the initial page chunk download while the session check runs (`router.tsx`, `initialPage`). Feature CSS loads with its page; `messages.css` is not in the first-load CSS.
- **A CI-enforced size budget** (`npm run size`), checked against the gzip JS and CSS that `index.html` loads.
- **Careful image handling.** One shared IntersectionObserver (`near-viewport.ts`) and a four-at-a-time download queue (`media.ts`). Reserved 3:2 boxes and per-photo aspect ratios stop layout shift. Object URLs are revoked. Photos stay out of persistent storage.
- **Render discipline.** `MessageRow` is memoized with stable callbacks. `MonthGrid` memoizes the grid and the event grouping. `matchMedia` and the IntersectionObserver are module-level. There is no `will-change`, no layout-property animation, and motion is limited to 140ms color and transform feedback.
- **48px targets everywhere**, including the task checkbox target, the message action summary, the day-number buttons (narrower but still 48px high on phones, as DESIGN.md allows), the composer links, the site footer, and stand-alone links (`.go`).
- **Long names hold.** With the stress data, nothing scrolls horizontally at any width. The top bar keeps one line per name with an ellipsis, badges wrap, and month cells clamp titles to two lines.
- **Public site.** Static HTML with no page JavaScript. Previews have a light and a dark source, explicit dimensions, `fetchpriority="high"` on the hero preview, and `loading="lazy"` below the fold.

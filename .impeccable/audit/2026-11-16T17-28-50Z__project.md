## Detailed Findings by Severity

### P1

**[P1] Eager thumbnail download on Memories**
- Location: `features/memories/components/MemoryImage.tsx:13`, `media.ts:5-22`, `queries.ts:19` (`p_limit: 50`)
- Category: Performance
- Impact: Every card runs `createSignedUrl` and then a `no-store` fetch on mount. One feed page means up to 50 RPCs and 50 downloads, and the cache drops them when the page closes. On mobile data the feed is slow and costly, and Today repeats the work for the latest memory.
- Recommendation: Keep the no-store blob rule from ARCHITECTURE.md. Gate the query with `enabled: nearViewport`, using one shared `IntersectionObserver` with about a 1-screen `rootMargin`. Cap concurrent downloads.
- Suggested command: `/impeccable optimize`

**[P1] Site dark palette drift**
- Location: `apps/site/src/site.css:25-44`
- Category: Theming
- Impact: Site dark values differ from `tokens.json` `darkColors`: canvas `#1C1A22` vs `#14111B`, muted `#B4AABD` vs `#A79EB4`, link `#C9B8EA` vs `#C9B5F7`, note `#3A2F25` vs `#2E2620`, focus, action, and 7 more. Light values match. The invite page's note panel renders brown and heavy, and a visitor who moves from site to portal sees two different "Midnight" themes. The source detector's `design-system-color` hits on 404, index, invite, privacy, support, and terms trace to this drift, so they are real.
- Recommendation: Generate the site's `:root` blocks from `brand/tokens.json` at build time with a small Vite plugin or prebuild script, so no copy is kept by hand. As a minimum, add a CI check that compares the two.
- Suggested command: `/impeccable polish`

### P2

**[P2] Day chip hides the day and clips the title**
- Location: `features/today/components/DayChips.tsx:10-12`, `styles/planning.css:64-65`
- Category: Implementation Integrity / Responsive
- Impact: Below 1200px the chip shows only the time. The capture shows "07:00 PM · Dinner…" for a Nov 17 event, while the 1440px panel says "NEXT PLAN · TOMORROW". `white-space: nowrap` in an `overflow-x: auto` strip cuts the title at the edge (390 and 768 captures). This is real CSS, not a capture effect.
- Recommendation: Reuse the next-plan label (Now/Today/Tomorrow/weekday) in the chip. Cap the chip width and use `text-overflow: ellipsis`, or let it wrap to two lines.
- Suggested command: `/impeccable clarify`, then `/impeccable adapt`

**[P2] Composer keystrokes re-render the whole conversation**
- Location: `features/messages/components/Conversation.tsx:43` (`body` state), `MessageRow.tsx:20`
- Category: Performance
- Impact: `setBody` re-renders `Conversation`. Every `MessageRow` (not memoized, inline callbacks) runs `DateTime.fromISO().setZone()` plus a format again. With older pages loaded, typing can lag on low-end phones.
- Recommendation: Move draft state into `Composer` and pass `onSend(body)`, or wrap `MessageRow` in `memo` with stable handlers.
- Suggested command: `/impeccable optimize`

**[P2] Nested scroll box for the conversation on phones**
- Location: `styles/messages.css:4` (`max-height: max(320px, calc(100dvh - 520px))`)
- Category: Responsive
- Impact: On an 844px phone the list gets about 324px inside a page that also scrolls. Pinned notes and a 3-line topbar sit above it. The clipped "Message 13" under the note card in the 390/768 captures is the box's top edge. The CSS has no sticky or fixed rule, so this is real behavior, but the full-height capture makes the box look taller than it is. The `520px` constant does not follow the header, notes, or composer heights.
- Recommendation: Below 1200px, let the page scroll the conversation, or make the Today column a flex column sized to `100dvh` minus the measured shell, so no magic offset is needed.
- Suggested command: `/impeccable layout`

**[P2] `Button` defaults to primary**
- Location: `components/ui/Button.tsx:2`; Settings `SettingsPage.tsx:56,65`
- Category: Implementation Integrity
- Impact: 31 `<Button>` uses have no `variant`, so retries and secondary actions render as primary. Settings shows "Save profile" and "Sign out on this browser" as primaries on one page (390-dark capture). DESIGN.md says one primary per page.
- Recommendation: Make `variant` required, or default it to `secondary`, and mark the single main action of each page explicitly.
- Suggested command: `/impeccable polish`

**[P2] Off-ramp type, radius, and unused spacing tokens**
- Location: `calendar.css:5` (24px), `:36` (6px radius), `:57` (11px); `base.css:53` (24px entry h1); `controls.css:24,30,35`, `calendar.css:9`, `planning.css:41`, `messages.css:24` (hard-coded 12px/20px radii); `main.tsx:15` emits `--space-*` with 0 uses
- Category: Theming
- Impact: Type steps of 11px and 24px are outside the DESIGN.md ramp, and 11px is below the smallest step (12px). The radius variables exist, but at least 8 rules bypass them, so a token change will miss those rules. The spacing tokens are generated but never used.
- Recommendation: Map 24px headings to `title` (19px) or `headline-mobile` (30px). Raise the 11px day count to the badge size (12px). Swap the literals for `var(--radius-*)`. Either use `--space-*` or stop emitting them; a missing token goes into tokens.json and DESIGN.md together.
- Suggested command: `/impeccable typeset`

**[P2] Public site does not use Manrope (proposal, owner decides)**
- Location: `apps/site/src/site.css:56`
- Category: Implementation Integrity
- Impact: DESIGN.md says "Manrope type in the browser". The site uses `system-ui`, so its headings differ from the portal and from its own preview images. Site h2/h3 sizes (28/32/20/18px) and the 22px brand also form a ramp that DESIGN.md does not document.
- Recommendation: Self-host one preloaded Latin Manrope variable woff2 (about 30 kB) with `font-display: swap`. This keeps Lighthouse 100. Record the site heading ramp in the DESIGN.md frontmatter.
- Suggested command: `/impeccable typeset`

Lift the feature signals into the shell, as with messages. *Performance*, `/impeccable optimize`.

## Patterns & Systemic Issues

- **Hand copies drift.** The one palette kept by hand (site dark) is the one that diverged. The portal palette, generated from the source, did not.
- **Literals beside tokens.** Radii, the 24px/11px steps, and all spacing are written as px, even though `--space-*` and `--radius-*` exist.
- **Compact views lose meaning.** The sub-1200px chip strip drops the day label, and the phone layout keeps a desktop-style inner scroll box.
- **Unsafe defaults.** `Button` → primary makes it easy to put more than one primary action on a page.
